# Django HW: Домашние задания по курсу «Фреймворк Django»

Учебный проект для курса «Python-разработчик». Содержит выполнение домашних
заданий по теме моделей и теме представлений и шаблонов в Django.

## Структура проекта
- `employees` — приложение для работы с информацией о сотрудниках.
- `workplaces` — приложение для работы с информацией о рабочих местах.
- `mysite` — конфигурационный проект (settings, urls).

## Как запустить проект

1. **Активируйте виртуальное окружение:**
   - Windows: `venv\Scripts\activate`
   - macOS/Linux: `source venv/bin/activate`

2. **Установите зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

3. **Примените миграции:**
   ```bash
   python manage.py migrate
   ```

4. **Создайте суперпользователя для входа в админку:**
   ```bash
   python manage.py createsuperuser
   ```

5. **Запустите сервер:**
   ```bash
   python manage.py runserver
   ```

## Тема 2: Модели, система администрирования и пользовательская модель

Сделано:
- Модель `Employee` (фамилия, имя, отчество, пол, должность).
- Модель `Skill` (навыки, тип, уровень освоения).
- Модель `Workplace` (номер стола, описание).
- Связь «один к одному» между рабочим местом и сотрудником (`OneToOneField`).
- Модели зарегистрированы в панели администрирования (`/admin`).
- Файлы миграций для всех приложений.

## Тема 3: Представления (views) и шаблоны (templates)

Сделано:
- Шаблоны подключены на уровне проекта.
- На уровне проекта подключены `media` и `static` файлы.
- К модели сотрудника добавлена необязательная галерея изображений
  с порядковым номером для ранжирования.
- Фото удаляются с диска при удалении записи из базы данных.
- Главная страница `/` — описание проекта и карточки сотрудников.
- Список сотрудников `/employees/` — карточки сотрудников.
- Подробная карточка сотрудника `/employees/<id>/` — доступна только
  авторизованным пользователям.
- Карточка сотрудника переиспользуется на главной странице и в списке.
- Все шаблоны наследуются от `base.html`.

## Тема 4: Запросы в БД

Сделано:
- К модели сотрудника добавлено поле `hired_at` (дата приёма на работу).
- Написан валидатор, запрещающий тестировщикам и разработчикам
  находиться за соседними столами. Проверка срабатывает при сохранении.
- Главная страница: общее количество сотрудников, 4 последних по дате
  приёма, в карточке — стаж в днях и первое фото.
- Список сотрудников: пажинация по 10 на странице, в карточке — стаж
  и первое фото.
- Детальная карточка: заглавное фото, пол, навыки с уровнями, стаж в днях,
  номер стола, галерея изображений (без первого).
- Запросы оптимизированы через `select_related` и `prefetch_related`.

## Тема 5: Тестирование

Сделано:
- 16 тестов (все проходят).
- Проверка доступности и контекста главной страницы.
- Проверка доступности, контекста и пажинации списка сотрудников.
- Проверка прав доступа к детальной карточке: без логина — редирект,
  с логином — доступ.
- Проверка валидатора соседних столов: разработчик и тестировщик рядом —
  ошибка, далеко — сохранение, два разработчика рядом — допустимо.
- Код отформатирован Black и isort.

## Тема 6: Django REST Framework

Сделано:
- DRF установлен и настроен, подключена JWT аутентификация (SimpleJWT).
- `GET /api/employees/` — список всех сотрудников (пажинация по 10).
- `GET /api/employees/?skills__name=...&hired_at__gte=...&hired_at__lte=...`
  — список с фильтрацией по навыкам и стажу.
- `GET /api/employees/<id>/` — подробная информация о сотруднике.
- `POST /api/employees/` — добавление сотрудника (только администратор).
- `PUT/PATCH /api/employees/<id>/` — изменение (администратор),
  смотритель может менять только рабочее место.
- `DELETE /api/employees/<id>/` — удаление (только администратор).
- `POST /api/token/` — получение JWT токена.
- `POST /api/token/refresh/` — обновление JWT токена.
- Разграничение прав: посетитель (чтение), смотритель (PATCH workplace),
  администратор (CRUD).

## Проверка задания тьютором

Если вы скачали проект к себе и хотите посмотреть, как он работает,
сделайте всё по шагам, по порядку, ничего не пропуская:

1. **Скачайте проект на компьютер.**
   На странице репозитория нажмите зелёную кнопку **Code**,
   выберите **Download ZIP** и распакуйте папку.
   Или, если знаете как, склонируйте репозиторий.

2. **Откройте папку проекта в редакторе кода** (например, VS Code).

3. **Создайте виртуальное окружение** (если его ещё нет).
   В терминале (внизу редактора) введите команду:
   ```bash
   python -m venv venv
   ```

4. **Включите виртуальное окружение.**
   - Windows: `venv\Scripts\activate`
   - macOS/Linux: `source venv/bin/activate`
   После этого слева в терминале появится `(venv)`.

5. **Установите зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

6. **Создайте таблицы в базе данных:**
   ```bash
   python manage.py migrate
   ```

7. **Создайте суперпользователя** (это ваши логин и пароль для входа
   на сайт и в админку):
   ```bash
   python manage.py createsuperuser
   ```
   Команда спросит: имя пользователя, адрес почты (можно пропустить,
   нажав Enter), пароль (вводите два раза, при вводе пароль не видно —
   это нормально).

8. **Запустите сервер:**
   ```bash
   python manage.py runserver
   ```
   В терминале появится адрес, например `http://127.0.0.1:8000/`.
   Нажмите на него или введите его в браузере — откроется сайт.

9. **Посмотрите страницы сайта:**
   - `http://127.0.0.1:8000/` — главная страница с карточками сотрудников.
   - `http://127.0.0.1:8000/employees/` — список сотрудников.
   - `http://127.0.0.1:8000/admin/` — админка (войдите под своим
     суперпользователем). Здесь можно добавлять сотрудников,
     рабочие места и навыки, а также загружать фото сотрудникам.

10. **Проверьте, что карточка сотрудника доступна только после входа:**
    - Откройте `http://127.0.0.1:8000/employees/1/` в обычной вкладке —
      сайт перенаправит вас на страницу входа.
    - Войдите (логин и пароль суперпользователя) — и карточка откроется.

Подсказка: если что-то пошло не так, начните с шага 1 и идите по порядку.
Чаще всего ошибки случаются, когда пропускают шаг 4 (не включили
виртуальное окружение).
